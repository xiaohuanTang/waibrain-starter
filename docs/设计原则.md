# 设计原则

日期：2026-11-15
背景与来源：基于爱玩社区《AI 原生新人类·装机包 v1》的四条设计原则与“内化优先”改写。
结论：这个包不是“功能堆叠”，而是用五条原则保证外脑能装上、能用起来、不把人掏空。

## 1. 零携带

**是什么**：包里没有任何具体人名、公司名、案例、历史数据，只有占位符。

**为什么**：帮别人装机时，顺手复制自己的库，会把你的信息永久写进对方的库。对方还没感受到价值，先多了一层信任负担。

**怎么做**：
- 只携带 `templates/` 和空白模板。
- 示例里不出现真实人名、公司名、联系方式。
- 装完检查一遍：`grep -r "你的名字" 对方的库/` 应该零命中。

## 2. 规则共建

**是什么**：沉淀标准是主人第一天亲手填的，写明“随时可改”。

**为什么**：规则如果从没和主人讨论过，AI 每次来问都会让人烦；规则如果由安装者代填，主人不会认。

**怎么做**：
- 宪法里的 Q1–Q3 由主人亲口回答。
- 填不出来先写“待定”，不要编。
- 在宪法里写明：对外脑的任何不满，第一反应是回来改这一页。

## 3. 分层镜像

**是什么**：库从第一天分 share-ok / private。上云、接飞书、给别的 AI 读的，永远只是 share-ok 的镜像。

**为什么**：收拾永远赶不上扩散；放宽永远比收紧容易。

**怎么做**：
- 建库当天就建 `private/`，写进 `.gitignore`。
- 拿不准的先放 `private/`。
- 每周复查一次 `private/待定/`：该升 share-ok 的移出去，该留的留下，没用的删掉。

## 4. 沉淀见光

**是什么**：每天一份日报，回答“外脑今天记了什么”。

**为什么**：看得见才谈得上信任，信任了才轮到自动化。黑箱记忆会让人不安。

**怎么做**：
- 用 `tools/deposit_report.py` 生成日报。
- 日报只列改动和新增，不贴隐私内容。
- 不满意就去改宪法里的沉淀规则。

## 5. 内化优先

**是什么**：装的不只是 AI 那一半，还有主人那一半的习惯。

**为什么**：AI 会越来越强；真正稀缺的，是关掉 AI 你自己还剩多少。用得爽不等于学到了。

**怎么做**：
- 护栏默认开：学习模式先反问，不直接给答案。
- 内化纪律写进宪法：先自己想、至少改一处、每周讲一遍、记下它错的、每两周关 AI 自测。
- 外脑只提醒和留痕，不替主人做这几件。
